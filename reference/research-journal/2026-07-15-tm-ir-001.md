# 2026-07-15 - Thermodynamic Program Envelope, Clamping, And Coordinates

## Paper Hook

This task supplies the logical-program boundary for the ThermoMap methods section and the
oracle-architecture figure. The envelope records which logical variables are free or observed,
preserves every source factor through exact substitution, and gives the evaluator a reversible
artifact whose projected energies can be checked without trusting the compiler output.

## Context And Roadmap Boundary

`TM-IR-001` was the sole dependency-ready task in `NEXT_TASK.md`; its dependency
`TM-VERIFY-01` is complete in `42c2409`. The pre-task repository contained immutable
`IsingModel` and `CategoricalModel` carriers but no common program object for clamps, logical
coordinates, observations, or source-factor identity. This task adds that target-independent
program layer. Placement, routing, target feasibility, higher-order lowering, imported THRML
programs, and new solver behavior remain assigned to later roadmap cards.

The bounded web audit compared three existing mechanisms. THRML declares ordered free and clamped blocks
and passes clamp values separately to its sampling routines. Dimod fixes a variable by removing
it from a BQM and also provides relabeling and BQM serialization. QUBOLite provides implicit
partial assignments for QUBO manipulation. None of those mechanisms supplies Gibbsiq's combined
logical-coordinate, observation, typed-label, source-factor, and immutable reconstruction
contract within the surveyed set. This finding is a mechanism comparison rather than an
exhaustive prior-art claim. Exact pairwise substitution is the complete production algorithm
for this task; exhaustive enumeration is reserved for the independent small-state oracle.

## Hard-Parts Analysis

### H1. The envelope must be immutable while preserving caller label identity

`ThermodynamicProgram` accepts exactly one audited `IsingModel` or `CategoricalModel`. It
derives `free_variables` and `clamped_variables` in model order. The dataclass bindings are
frozen, mappings are read-only, and supported mapping/sequence/set-shaped program evidence is
recursively frozen. A caller-supplied custom object receives a defensive deep copy but may
retain its own mutating methods; portable immutable evidence therefore uses the supported
container and scalar types. Mappings supplied in a different insertion order normalize to the
same program payload.

Arbitrary hashable labels remain the actual in-memory keys. The implementation does not sort,
match, or relabel variables through `repr()`. Valid Ising and categorical reconstruction now
uses positional diagnostic context, so a label with a stateful `__repr__` receives zero calls
during projection and relabeling. Serialization refuses an unsupported opaque label explicitly
instead of assigning it a process-specific string identity.

### H2. Clamp projection must preserve the complete energy and model type

`EVAL-EQ-023` records direct substitution before production code. For an Ising free variable
`i`, every incident free-clamped interaction adds `J_ij c_j` to the surviving linear
coefficient. Clamped linear and clamped-clamped quadratic terms add to the offset. The
categorical path applies the corresponding unary and pair-table substitutions in the stored
endpoint orientation.

For free categorical variable `i`, category `a`, and clamped set `C`, the implementation uses

```text
U_i^C(a) = U_i(a) + sum_(j in C) V_ij(a, c_j)

offset_C = offset
           + sum_(i in C) U_i(c_i)
           + sum_(i<j; i,j in C) V_ij(c_i, c_j).
```

`V_ij` is indexed in the canonical stored endpoint orientation. Free-free pair tables retain
their coefficients. The constructor traverses and validates retained tables, so categorical
runtime is proportional to the total unary and pair-table cardinality of the reconstructed
model; the substitution arithmetic itself visits the relevant incident table slices. Each
derived unary value and offset is accumulated with `math.fsum` in canonical source-factor
order.

For one stored pair `(p, q)`, the explicit cases are: retain `V_pq` when both endpoints are
free; add `V_pq(a, c_q)` to `U_p(a)` when only `q` is clamped; add `V_pq(c_p, a)` to `U_q(a)`
when only `p` is clamped; and add `V_pq(c_p, c_q)` to the offset when both are clamped. This
case split resolves the argument order when the clamped endpoint precedes the free endpoint.

Projection returns the same model type. A fully clamped program returns a zero-variable model
whose offset equals the source energy of the complete clamp assignment. An empty clamp set
retains every coefficient and offset. Isolated clamped variables still contribute their linear
or unary value to the projected offset. `math.fsum` and the existing finite-number validators
retain the project's finite arithmetic contract.

### H3. Provenance has distinct source and destination coordinate systems

Factor identities use source-model positions: `linear:i`, `quadratic:i:j`, `unary:i`, and
`pairwise:i:j`. Every factor receives a stable source identity, including zero unary or linear
factors. Projection emits one transformation record per source factor and records whether that
factor survives as a linear/unary term, survives as a pair term, or collapses into the offset.

Independent review found that the first implementation used source positions for destination
keys. Clamping the first variable of a three-variable model therefore produced a valid energy
and an invalid lineage address. The correction retains source positions in factor IDs and uses
the compact projected order for `variable_position`, `left_position`, and `right_position`.
Both coordinate systems now remain explicit and independently checkable.

Every transformation row contains `factor_id`, `source_id`, and `target_kind`. A `linear` or
`unary` destination adds `variable_position`; a `quadratic` or `pairwise` destination adds
`left_position` and `right_position`; an `offset` destination adds no position. Factor IDs are
unique and complete. Source IDs are non-empty strings and may repeat when several normalized
factors descend from one caller source. Several factors contributing to one derived coefficient
remain separate transformation rows; lineage records additive parentage and never reconstructs
the coefficient.

### H4. Clamp validation must reject Python aliasing rather than inherit it

The constructor accepts either a mapping or an ordered sequence of `(variable, value)` records.
Ordered records preserve enough information to reject a repeated equal assignment as a
duplicate and a repeated unequal assignment as a conflict before a dictionary can erase the
evidence. Unknown variables fail explicitly.

Ising clamps require exact built-in integers `-1` or `+1`; booleans and numeric aliases fail.
Categorical clamps require equality and exact type with one declared domain category. A Boolean
that compares equal to an integer category is reported as a Boolean alias. This rule prevents
Python's `True == 1` behavior from silently changing a logical observation.

### H5. Coordinates and observations need a logical-only contract

Logical coordinates are optional finite, non-empty numeric tuples with one consistent
dimension across every supplied variable. If no coordinate is supplied, `coordinate_dimension`
is zero. If a subset is supplied, the dimension is the common positive tuple length and
uncoordinated variables are absent from the coordinate mapping. Coordinates retain model order and carry no target cell,
tile, route, distance unit, or topology claim. Physical mapping remains a later compiler stage.

Observation metadata is keyed only by clamped variables. Reconstructing a program with a
smaller clamp set retains evidence for variables that remain clamped and drops evidence whose
observation role was removed. This gives immutable unclamping semantics without preserving a
false observation association.

### H6. Serialization must be reversible without stringified keys

Schema version `1` uses positional model and program records plus typed values for `None`,
Boolean, integer, finite float, string, bytes, tuple, and frozenset labels. Metadata mappings and
sequences use typed recursive records with canonical key ordering. The decoder requires an
exact integer schema version; independent review caught and closed the initial acceptance of
JSON `true` and `1.0` through Python equality.

The categorical payload preserves `reversed_pair_count`, which is public normalization evidence
on `CategoricalModel`. Serialized quadratic and pairwise factors must use canonical source
order, and the factor-source table must cover the complete logical model. Duplicate clamp,
coordinate, observation, factor, and source records fail before reconstruction. Unsupported
opaque labels fail without a `repr()` call or pickle fallback.

The root payload contains `schema_version`, `model`, `clamps`, `coordinates`, `observations`,
`factor_sources`, and `metadata`. An Ising model record contains kind `ising`, typed `variables`,
an order-aligned `linear` list, positional `quadratic` rows, `offset`, `source_format`, and typed
`metadata`. A categorical model record contains kind `categorical`, typed `variables`, aligned
`domains` and `unary` rows, positional pair matrices, `offset`, `reversed_pair_count`, and typed
`metadata`. Clamp, coordinate, and observation rows identify variables by source position.

Typed scalar tags are `none`, `bool`, `int`, `float`, `str`, and `bytes`. Integers use decimal
strings, floats use finite hexadecimal strings, and bytes use validated base64. Label containers
use `tuple` or canonically sorted `frozenset` items. Emitted metadata containers use `mapping`
rows and `list` items; mapping rows sort by the canonical JSON representation of each typed key,
so heterogeneous supported keys require neither Python comparison nor `repr()`. The decoder
checks row shapes, positions, duplicates, finite coefficients, canonical pair order, and complete
factor-source coverage before model construction.

### H7. Result reconstruction must prevent provenance forgery

`SampleResult.from_program` accepts free-variable Ising samples in `SPIN` or `BINARY` form,
inserts every clamp in original model order, and recomputes total and interaction energies from
the original model. Result metadata records schema version plus free and clamped source
positions. Canonical program provenance overwrites conflicting caller metadata. A regression
caught the first implementation's reverse precedence, which allowed a caller to claim schema
`999` and a forged clamp position.

Categorical sampling remains a later runtime task. The envelope and categorical projection are
complete here; `SampleResult.from_program` returns a structured refusal for a categorical
program rather than inventing execution semantics.

### H8. The oracle must not echo production coefficients

The public oracle enumerates free assignments, merges each with the original clamp mapping, and
evaluates the source model directly. It compares that energy with the projected model using
`rel_tol=0.0` and `abs_tol=1e-9`. The expected path never calls the production projection helper
and never copies projected coefficients.

The recorded generator extends this check to 42 fixed-seed programs and 248 free assignments.
Its expected path merges clamps and independently sums the original offset, unary/linear, and
pair factors with `math.fsum`; it calls neither `model.energy` nor `program.project`. The actual
path evaluates the projected model.
It also serializes and reconstructs every program and validates every lineage destination
against the projected model. The maximum measured absolute energy error is `0.0`; all 42
serialization and lineage checks pass.

The coordinator also ran an exploratory fixed-seed audit with seed `734019`: 120 generated
Ising programs, 80 generated categorical programs, 835 enumerated energy comparisons, and 200
JSON round trips all passed at the same tolerance. Its inline script was not retained, so this
result is recorded as a non-closing exploratory check. The reproducible 42-case generator and
raw corpus supply the closure evidence.

## Engineering And Reasoning Worklist

The bounded task required these engineering components:

1. The immutable `ThermodynamicProgram` schema and normalized free/clamped ordering.
2. Strict clamp, coordinate, observation, and factor-source validators.
3. Same-type Ising and categorical projection, including zero-variable constants.
4. Source-factor lineage with separate source and projected positions.
5. Immutable clamp reconstruction and complete-bijection relabeling.
6. Versioned typed-label serialization and strict duplicate-aware decoding.
7. Ising result expansion and package-level public exports.
8. Direct public oracles, metamorphic tests, deterministic raw artifacts, and checksums.

The task required these reasoning decisions:

1. Derive both substitution formulas under the audited energy conventions and preserve offsets.
2. Decide how a collapsed factor retains identity after becoming a unary term or constant.
3. Separate logical coordinates from future physical placement and topology coordinates.
4. Define duplicate, conflicting, Boolean-alias, and exact-type categorical semantics.
5. Preserve arbitrary hashable labels in memory while bounding the reversible JSON label set.
6. Define immutable unclamping as reconstruction and decide how observation evidence follows it.
7. Distinguish source positions from destination positions after variable elimination.
8. Keep the independent oracle structurally separate from production coefficient construction.

## Decisions

1. We use direct factor substitution. Ising projection is `O(V + E)`. Categorical projection
   traverses the unary entries and pair-table entries required to reconstruct and validate the
   surviving model, with substitution arithmetic over incident clamp slices. No combinatorial
   search is required by production projection.
2. We reserve exhaustive enumeration for small-state verification. It checks every free state
   and does not determine production coefficients.
3. We return the same logical model type after projection. A fully clamped model contains zero
   variables and the complete energy in its offset.
4. We normalize free variables, clamped variables, clamps, coordinates, observations, and factor
   sources against source model order.
5. We accept mapping or ordered-pair clamp input. Ordered input exposes duplicates and conflicts
   that a Python mapping cannot represent.
6. We require exact built-in Ising spins and exact-type categorical membership. Silent Boolean,
   floating, or string coercion is outside the logical contract.
7. We store finite logical coordinates as floats and require one dimension across supplied
   coordinates. A program with no coordinates carries dimension zero; a partially coordinated
   program carries the common positive dimension and omits uncoordinated variables from the
   coordinate mapping.
8. We associate observation metadata only with clamped variables. `with_clamps` filters evidence
   to the reconstructed clamp set.
9. We use positional factor IDs and non-empty string source IDs. Position supplies a stable key
   without serializing a label through `repr()`.
10. We use an exact integer schema version and positional JSON records. Typed labels preserve the
    supported label type, and opaque labels remain supported in memory with explicit serialized
    refusal.
11. We require relabel mappings to cover every source variable exactly and to produce unique,
    hashable targets. Relabeling preserves variable positions and categories, remaps model,
    clamp, coordinate, and observation keys, copies model/program metadata, and retains the
    positional factor/source mapping. Factor IDs remain unchanged because the bijection does not
    reorder source positions.
12. We preserve categorical pair-normalization evidence across serialization. Reversed input
    count is part of the public audited model state.
13. We expose `ThermodynamicProgram` and `PROGRAM_SCHEMA_VERSION` from `gibbsiq`. The package name
    and production API boundary remain Gibbsiq rather than ThermoMap.
14. We generate raw artifacts with seed `20260715` and require explicit `--overwrite` for any
    regeneration. The second default invocation failed as designed with `FileExistsError`.

## Rejected Alternatives

- Mutating the source BQM or model in place was rejected because it erases the unclamped logical
  object and makes reversible provenance harder to establish.
- Delegating validation to dimod's `fix_variable` was rejected because its documented value may
  differ from the model vartype. Gibbsiq requires exact clamp-domain membership.
- Using a THRML sampling program as the logical envelope was rejected because that object binds
  the model to executable blocks and schedules. `ThermodynamicProgram` is the target-independent
  input to later THRML lowering.
- Applying persistency or optimization algorithms such as QPRO+ was rejected because the caller
  supplies the clamp assignment. The task verifies substitution rather than inferring fixed
  variables.
- Stringifying labels or using `repr()` as a stable identity was rejected because two labels can
  collide and process-specific addresses cannot round trip.
- Pickling opaque labels was rejected because it creates an executable, environment-specific
  wire format. Unsupported labels remain usable in memory and fail JSON serialization clearly.
- Mutating `unclamp()` was rejected because immutable reconstruction makes the prior observation
  state auditable.
- Storing physical cells or target routes beside logical coordinates was rejected because
  placement and routing have later dependency cards.
- Dropping clamped factors after coefficient folding was rejected because later compiler audits
  need to trace a derived unary term or offset contribution back to its source.
- Letting caller result metadata override canonical clamp provenance was rejected because it
  enables a forged audit record.
- Reusing production projection to compute expected oracle coefficients was rejected because a
  sign or offset defect would appear on both sides.
- Silently overwriting golden evidence was rejected because a formula or schema change requires
  an explicit new run or an explicit recorded regeneration.
