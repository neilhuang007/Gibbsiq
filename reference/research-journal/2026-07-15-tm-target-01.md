# 2026-07-15 - Provenanced TSU Target And Topology Contract

## Paper Hook

This task supplies the target-description boundary for the ThermoMap methods section and the
target-assumption table: every hardware fact is either explicit with provenance and a declared
sensitivity scenario or explicitly unknown. It also supplies independently enumerated topology
fixtures for the oracle-architecture figure and prevents an agent from improving its score by
quietly inventing unavailable Z1 parameters.

## Goal And Roadmap Audit

`Project_GOAL.md` asks for a mixing-aware, target-aware compiler and profiler whose hardware
inputs cover topology, tile geometry, permitted interactions, degree, precision, update time,
cell energy, communication, programming, and host transfer without converting assumptions into
facts. The live roadmap assigns exactly that prerequisite to `TM-TARGET-01`, before placement,
routing, and physical profiling consume it. The goal and roadmap therefore match; no roadmap
rewrite was warranted in this lane.

The implementation is deliberately a declaration and validation layer. It does not infer a
topology from a logical model, place or route variables, calibrate a device, or claim that an
assumed target is Z1.

## Hard-Parts Analysis

### H1. Unknown hardware facts must survive serialization

`TSUSpec` schema `tsu-target-v2` adds an explicit topology, accumulator format, communication,
host-transfer, and programming/reprogramming groups while retaining the existing scalar
contract. Every absent scalar or group serializes as `null`; an empty supplied group serializes
its individual facts as `null`. This distinction lets later compiler stages tell "the group was
considered but this fact is unknown" from an omitted legacy declaration without substituting a
default.

Supplied top-level target values require a matching `ParameterProvenance`. In the complete v2
contract, numeric facts require a finite sensitivity range in the matching unit and nonnumeric
facts require either a sensitivity range or a sensitivity note. `measured`, `modeled`, and
`inferred` external facts require an access date. A `measured` fact additionally requires the
path or identifier of a raw evidence artifact. These rules block modeled energy, circuit-level
RNG timing, and complete-device measurements from being collapsed into one evidence class.

The pre-existing scalar-only partial contract remains readable so current hardware-assessment
fixtures do not silently change semantics. The stricter gate activates as soon as any new v2
target group is supplied. This compatibility boundary is explicit rather than a hidden fallback.

### H2. Topology needs executable adjacency, not a label

`GridTopology` represents a finite open grid with caller-supplied shape, origin, tile shape, and
neighbor offsets. Offsets must be dimensionally valid, nonzero, duplicate-free, and
inversion-symmetric because the declared physical graph is undirected. Tile dimensions divide
the corresponding grid dimensions exactly. `ExplicitTopology` represents canonical integer
nodes `0..n-1` and a duplicate-free set of undirected simple edges. Both records provide stable
serialization, capacity, neighbors, degrees, edge admissibility, and unweighted shortest-path
distance.

The tests construct expected grid edges from Cartesian products and displaced coordinates
without consuming production summaries. They cover 48 combinations of small shapes and
nearest, diagonal, or stride-two offset families. A separate independent adjacency builder and
breadth-first search check every one of the 1,099 simple undirected graphs through five nodes.
These checks guard boundary handling, canonical edge orientation, degree, disconnected distance,
and reorder/translation invariance.

### H3. Physical values require canonical units and sensitivity boundaries

`PhysicalQuantity` accepts finite SI values only: seconds, hertz, joules, joules per bit, or bits
per second. Callers convert `ns`, `fJ`, and vendor presentation units before construction. This
choice avoids an implicit rescaling table whose rounding behavior would become part of the
hardware truth contract. Communication bandwidth and clock must be positive; latencies and
energies may be zero but not negative. Every value lies inside its caller-declared sensitivity
range.

The sensitivity ranges recorded here are analysis scenarios, not uncertainty intervals reported
by a source. In particular, the paper-modeled target uses a declared factor-of-two scenario
around `2e-15` joule per cell update and a declared timing scenario around `1e-7` second. The
former is classified `modeled`; the latter is classified `inferred` from circuit RNG
autocorrelation and explicitly is not a complete-cell timing measurement.

## Decisions

1. We use open-grid boundaries and explicit offset vectors. Periodicity, wraparound, and a
   "nearest-neighbor" label were rejected because each would guess edges not supplied by the
   target owner.
2. We require the additive inverse of every grid offset. Directed communication can be added by
   a future link-level schema; the current compiler graph and Ising couplers are undirected.
3. We use canonical integer node indices for explicit target graphs. Arbitrary Python labels
   were rejected because they weaken deterministic JSON and do not add physical meaning.
4. We distinguish coefficient and accumulator formats. A coefficient that fits an input field
   does not prove that the local-field accumulation fits the arithmetic path.
5. We retain `cell_energy_joules` and `cell_update_seconds` as backward-compatible top-level
   values while adding structured physical quantities to communication, transfer, and
   programming groups. A flag-day conversion was rejected because it would invalidate the
   existing independently tested hardware-assessment contract.
6. We cap a fixed-point code at 53 bits, preserving the existing exact-binary64 integer-code
   decision. This task did not change rounding, overflow, or the canonical Ising energy
   convention.
7. We supply no Z1 topology, precision, communication clock, link cost, host cost, or programming
   default. Current public material does not establish a stable complete-device contract for
   those values.

## Limitations And Follow-Up

`GridTopology.maximum_degree` and `edges()` enumerate cells, which is appropriate for the small
verification targets but can be costly for extremely large declared grids. Later mapping code
should avoid materializing full topology summaries when a closed-form or streamed check is
available and independently verified.

This contract does not decide whether a logical problem embeds, how variables are placed, how
paths are routed, whether quantization preserves an optimum, or whether a timing/energy model is
calibrated. Those remain dependency-ordered follow-ups in `TM-MAP-001` through `TM-MAP-003`,
`TM-NID-001`, `TM-NID-002`, `TM-COST-001`, and `TM-PROF-001`. The coordinator owns public
exports, ledger transition, integration commit, and push.
