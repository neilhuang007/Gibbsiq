# 2026-07-15 - Artifact-Only Inspector Core

## Paper Hook

This work supplies the reporting side of the evaluation contract: a stored stochastic result
produces a deterministic report while objective claims remain unavailable until a
caller-supplied model passes independent all-row checks. It feeds the methods section on
evidence provenance and the figure showing raw artifacts flowing into auditable summaries.

## Context

`SampleResult` already stores samples, total and interaction energies, traces, diagnostics,
and metadata. It does not store the canonical linear and quadratic coefficient table. The
Inspector therefore separates artifact-consistency facts from objective-verification facts.
The core consumes one stored result and optionally one caller-supplied `IsingModel`; HTML,
CLI, comparisons, compiler manifests, topology, baselines, and thermodynamic profiling remain
assigned to `TM-REP-001`.

The task uses EVAL-EQ-001 without changing its convention:

```text
E(s) = offset + sum_i h_i s_i + sum_{i<j} J_ij s_i s_j
```

No stochastic step or external performance claim occurs in this task. The stored artifact
uses seed `481` only to demonstrate metadata preservation. Inspector executes no RNG or
sampler.

## Hard-Parts Analysis

### H1. Stored best-row selection is distinct from objective verification

The report recomputes the first argmin of stored `interaction_energies`. It then selects the
sample, stored interaction energy, and stored total energy from that same row. This rule
preserves offset-stable selection and exposes a corrupt row instead of minimizing a second
array to manufacture a consistent-looking answer. Without a model, the association and
objective-recomputation states are `not_available` with a reason.

With a model, exact variable-tuple equality and a `SPIN` or `BINARY` result vartype precede
energy checks. Every row is recomputed through `IsingModel.energy` and
`IsingModel.interaction_energy`. Each stored value uses zero relative tolerance and absolute
tolerance `1e-9`, imported from `benchmark_oracle.DEFAULT_TOLERANCE`. A mismatch identifies
its field and row and raises `ValueError`; no partially checked association is emitted.

### H2. The model fingerprint identifies the positional energy table

The fingerprint payload schema is `gibbsiq.ising_energy.v1`. It stores the `SPIN` vartype,
variable count, signed-zero-normalized `float.hex()` offset and linear coefficients, and sorted
`[left_position, right_position, coefficient_hex]` edges. Canonical JSON uses sorted object
keys, compact separators, UTF-8 bytes, and SHA-256. Metadata and label values do not enter the
digest. The report records the separately checked variable order through positional label
tokens.

The independent test encoder reproduces the payload outside Inspector and pins digest
`a7b042c433de7bb4c0ec3d71cfa63296019744fcfaae2f2d0761874a75291ff5` for the public two-spin
case. Coefficient and asymmetric order mutations change the digest. Metadata and custom-label
`repr` mutations do not. Positive and negative zero produce the same digest.

### H3. Arbitrary evidence requires deterministic JSON without process identity

String-keyed trace, diagnostic, and metadata maps retain their fields. Non-string maps use
sorted `mapping_entries_v1` records. Built-in immutable labels use tagged encodings; arbitrary
objects retain their module-qualified type and positional role while excluding `repr` and
object identity. Bytes, sets, and non-finite floats use explicit finite encodings.

The coordinator's independent review found that sorting non-string map entries only by their
encoded key left a tie for two opaque objects of the same type. Python's stable sort then
retained insertion order. The corrected implementation sorts the complete encoded entry, and
the regression reverses two same-type opaque keys with distinct values. Both inputs now emit
identical JSON without invoking either `repr`.

### H4. Hostile labels must not escape Markdown evidence

Markdown includes the complete deterministic JSON under a backtick fence longer than every
backtick run in the payload. A test label contains five backticks, a forged table row, and a
script tag. The report uses a six-backtick fence, keeps the label inside the code block, and
remains byte-stable across repeated renders.

## Decisions

1. We use summary schema `gibbsiq.inspector.summary.v1` with explicit `artifact`,
   `stored_energies`, `best_row`, `model_association`, `traces`, `diagnostics`, `warnings`,
   `metadata`, and `availability` fields.
2. We retain unknown diagnostic keys as stored evidence. Only `diagnostics.flags` receives the
   source-preserving `warnings` view; the Inspector invents no thresholds or health verdicts.
3. We represent best samples as values aligned to a recorded positional variable order. This
   avoids JSON object-key coercion and collisions for mixed or custom labels.
4. We freeze the in-memory summary and detach every `to_dict()` result. Caller mutation of one
   serialization cannot alter later reports.
5. We preserve raw `SampleResult` as the source artifact. Opaque Python objects retain type and
   position in the summary; reconstruction of their identity is outside the report contract.

## Rejected Alternatives

- Trusting `SampleResult.best_index` or `best_sample` was rejected because the public oracle
  must recompute the first-tie selection outside the convenience property.
- Minimizing total energies was rejected because a large offset can collapse distinct totals
  to the same binary64 value while interaction energies retain the objective order.
- Set equality for model variables was rejected because coefficient and sample interpretation
  depends on exact tuple order.
- Inferring a model from metadata, an offset, or a caller-provided checksum was rejected because
  `SampleResult` lacks the coefficient table needed to check the claim.
- Label `repr`, pickle, object hash, and object identity were rejected because their encodings
  can vary across processes and can execute or expose object-specific behavior.
- Sampler replay was rejected because a report must remain reproducible when THRML execution is
  disabled and replay would create a new stochastic artifact.
- HTML and compiled-manifest association were rejected from this lane because their producing
  schemas and integration gates belong to `TM-REP-001` and `TM-API-001`.

## Limitations And Follow-Up

The core emits in-memory dictionaries, JSON text, and Markdown text. It does not write report
bundles, compare runs, open a browser, render HTML, infer constraints, or claim topology,
hardware, profile, or baseline evidence. `TM-REP-001` closes those integration gaps after
`TM-API-001`, `TM-PROF-001`, and `TM-BENCH-001` stabilize their artifacts. The coordinator
owns public `gibbsiq.__init__` export, ledger transition, integration commit, and final shared
static rerun.
